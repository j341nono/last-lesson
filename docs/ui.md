# 画面と映像の方針

## スクロールを要求しない

アプリを `100dvh` の画面に収め、ヘッダー、内容、フッターの高さを配分する。内部をスクロールする引き出しや長い一覧は使わない。単にoverflowを隠して読み物を切り捨てるのではなく、内容をページ化する。

- プロローグは3カット。教えの入力・解釈確認も1つずつ3ページ。
- 長い教えは短い引用を入口にし、原文ボタンから全文をページで確認できる。
- 旅は映像、短い字幕、判断/進行ボタンを同じ画面に表示。数値や詳しい理由は必要なときだけ開く。
- 介入は3つの元の教えを切り替えて選ぶ。教えを追加したり行動を直接指定したりしない。
- エンディングは結末・三つの教え・出会いと約束・年表の4タブ。年表は1イベントずつ。
- 記録は2件ずつのページ。詳細説明もスクロールしないダイアログ内でページ送りする。

モバイルの縦画面と横画面は配置を変える。横向きの旅は映像と字幕を左右に並べ、狭い縦画面では上下に並べる。ダイアログはnative dialogでフォーカスを閉じ込め、閉じたら元の操作へ戻す。Escapeでも閉じられる。

## 短いピクセルアニメーション

`FilmScene` は実際のイベント・確定した行動から演出を選ぶ。接近、救助、会話、約束、探索、修理、建設、別れ、解放、対立、休息をCanvasで描く。旅人が起き上がる、光を受け渡す、装置を走査する、修理の火花が散る、といった小さな動きで出来事を伝える。

原則として行動の動機に対応する演出を使い、修理結果や建設などは実際の行動・効果で補正する。海を見た記憶には海岸を、レンの空席には人物のいない工房を表示する。48イベントそれぞれに独立した動画を用意した構成ではなく、背景・人物・行動の演出を組み合わせる方式。

事前執筆した文章を最大44文字の字幕カットに分割し、情報を落とさず、短い単位で表示する。自動字幕送りは3.2秒以上を確保し、文字数に合わせて伸ばす。手動送り・停止・映像の再生を用意し、手動の選択は次のシーンでも維持する。詳細や介入を開いている間は字幕の自動送りを止める。

映像の時計は `performance.now()`、シミュレーションの乱数は保存したシード状態で分離する。何秒眺めても、再生し直しても、判断や寿命は進まない。`prefers-reduced-motion` では動きを止め、分かる静止ポーズを表示する。ナレーションや動画生成APIは使っていない。
