# ゲーム設計・データ仕様

## コンセプトとルール

「三つの価値観から、一つの人生が生まれる」。プレイヤーは先生であり、毎回の行動選択者ではない。救助、真実、約束などが矛盾する出来事を通じ、善意の結果と本人の意図の距離を描く。救助、被害、稼働年数、復興、信頼を別々の指標として扱い、合計点は作らない。

教えの入力→解釈確認→旅→出来事→自律的選択→結果/理由→次の出来事→終焉→年表、というループ。クリックを急ぐこともできるが、本文・理由・結果の読解を含め10〜15分を想定する。強制的な待ち時間は設けない。プレイ時間の実測は今後必要。

## アーキテクチャ

- `src/game/model.ts`: 共有型・教えの検証。
- `src/game/lessons.ts`: 単純なキーワード分類とクライアント解析窓口。
- `src/game/scenarios.ts`: 48ノード、各2行動。旅人・少女・村・機械・戦争・データ・森・雪・知性・自己・工房・未来の12アーク。
- `src/game/engine.ts`: シード乱数、候補抽選、行動抽選、状態変化、終焉、再実行。
- `src/game/validation.ts`: イベントのZodスキーマ。
- `src/storage.ts`: IndexedDBの途中保存と完結記録。
- `src/components/PixelWorld.tsx`: Canvas描画。
- `src/App.tsx`: 画面遷移とプレイヤー操作。エンジンへ行動IDを渡さない。
- `server/index.ts`: 解析API、検証付き投稿、D1ランキング。

## イベントデータ

|フィールド|意味|
|---|---|
|id / arc|不変IDと連続シナリオ群|
|stage|0〜3。6イベントごとに次時代の候補が開く|
|title / text|事前執筆した日本語の出来事|
|region / scene|地域と8種類の背景キー|
|requires|必要な過去の記憶。未成立なら出現しない|
|weight|候補の正の抽選重み|
|critical|教えの優先度に介入できる局面|
|years|基本の経過年数|
|actions|選択可能な行動（2以上）|
|next|因果のある後続ノードへの明示的な参照。抽選は後続だけに固定しない|

行動は `label, result, motive, traits, effects, memory, life, requires?` を持つ。`life` は期待寿命の増減、`requires` は追加の必要記憶。人物や約束は現在、名前付き記憶で保持する。独立した人物オブジェクトや複雑なAND/OR条件DSLは未実装。

候補は未訪問かつ時代・記憶条件を満たすものだけ。新しい時代のイベントは2倍、回収イベントは基本3倍に重み付けする。48ノードを毎回全部通るわけではない。同一ノードの再訪は認めず、無限ループを防ぐ。

例えば「アオを救った」が後の修理・軍事工房・手紙の条件になる。修理による寿命・被害・信頼の変化は、他アークでも寿命や判断に作用する。工房やミナとの経験が、別の出来事で社会的な行動を選びやすくする。記憶の因果は結果と理由に記録する。

## 状態と判断

8性格値：共感性、好奇心、慎重さ、自己保存、誠実さ、社会性、自律性、攻撃性。初期42を基準に教えで最大82まで補正、経験で5〜95へ変化。現状、慎重さは保存されて成長するが、単独の係数としては未使用。

状態には年齢、期待寿命30年（23〜36年の範囲）、エネルギー0〜100、損傷0〜95、素材、信頼、救助、被害、復興、記憶、判断履歴を持つ。素材があり損傷が大きいと自動整備、低エネルギーでは寿命と損傷に追加の負担が生じる。

行動重み = 基礎値 + 対応性格値/24 + 教えの適合（強さ×1.65×対象係数）+ 生存上の必要 + 記憶の影響。危険時の教えはエネルギー40未満か損傷20超、葛藤時の教えはcriticalイベントだけで有効。対象は自己/他者/世界で適合度を0.8〜1.3倍にする。介入した教えの寄与だけ一時4倍にし、抽選そのものは残す。

各判断の理由は最大寄与の教え、または性格、イベントを引き起こした記憶、介入を説明する。これは確率への寄与の説明であり「その教えが必ず行動を決めた」という証明ではない。乱数も結果に関わる。

現在は8性格値のうち主として各動機の代表値を使う簡潔なモデル。能力値による成功失敗の抽選や資源の最低必要量は今後の拡張領域。

## 時間と終焉

基本1イベント1.1年。後半は残り年数を最大28イベントまでに分配し、長い平穏な時間も経過する。最低20の出来事を目安とし、期待寿命に達したら停止する。候補の尽きた旅や28イベント終了時に寿命が残れば、その後の静かな年月を明示して最期まで見届ける。年表の出来事の日付を後から改変しない。

エンディングは被害、復興、救助、信頼、自律、その他の順で6種類に分類。分類の優先順は物語テンプレートの選択であり、善悪の順位ではない。最後の言葉、主要判断、8性格の変化、各教えが判断に寄与した回数を表示する。

## LLM仕様

`POST /api/analyze` に `{texts: [string,string,string]}`。各教え1〜100字。API接続は12秒、画面側は15秒で打ち切る。環境変数で指定した互換Chat Completions endpointに1リクエストだけ送る。モデルがJSONオブジェクトを返せる必要がある。

返り値は `lessons` と `source: llm|local`。各Lessonは `text, meaning(1〜160字), motive(8種類), strength(1〜3), target(others/self/world), condition(always/danger/conflict)`。Zodで検証し、原文はユーザーの入力で上書きして保持する。エラー・応答不正・未設定・解析レート超過時はローカル分類に落ちる。旅のエンジンはネットワークを一切呼ばない。

meaningは表示用の解釈文であり、自由記述の修正だけでは動機は変わらない。行動原理・強さ・対象・適用場面を編集することで計算に反映される。ローカル分類は高度な自然言語理解ではないため、画面に解析元を明示する。

## ビジュアル方針

灰緑の背景、淡い生成りの文字、真鍮色の操作要素。明朝体のタイトルとゴシック体の本文を組み合わせる。フォント取得ができなくてもシステムフォントで遊べる。

背景は480×260のCanvasを最近傍拡大。荒野、街、集落、研究所、データセンター、森、雪、復興地を、同じパレットと矩形から独自に構成。ロボットはアンテナ、光る目、胸の電源、布の目印を持ち、年齢による錆と損傷を重ねる。意図的に簡素な描画であり、専用の生成画像・人物立ち絵は未制作。

Canvasの呼吸・粒子は装飾であり乱数シミュレーションに関わらない。prefers-reduced-motionでは静止。音は初期オフ、ユーザーが有効にした場合だけ短いWeb Audio音を鳴らす。
