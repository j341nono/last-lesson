# テスト方針

## 自動検証

`npm test` はVitestで以下を検証する。

- 48イベントのZod検証、ID一意性、正の重み/年数、参照先の存在。
- 記憶の生産元の存在、初期ノードからの固定点探索による到達性（循環だけで閉じた依存を検出）。
- 1,000異なるシードの完走、20〜28の重複なしイベント、寿命の終わりまで進むこと、必要記憶の順序、説明文、全48イベントへの到達、多様な展開。
- 同じシード・教えから同じ完全状態、JSON保存/復元後にも同じ状態。
- 300同一シードの対照比較。救助系と支配系の教えで救助/被害に20%以上の傾向差があること。
- 重要局面だけで2回まで介入でき、3回目を拒み、履歴から再実行できること。
- APIキーなしの分類、入力不正・サイズ超過・cross-origin拒否、DBなしの明示的な状態、同意必須、投稿レート、偽のスコアの再計算。
- 人物との出会い、果たした/破った約束、犠牲者数とシナリオ結果の整合性。

`npm run test:e2e` はPCとスマートフォンのviewportで、タイトル→プロローグ→入力→修正確認→全人生→エンディング→保存記録→リロード後の記録を確認する。画面横溢れを検出する。タイトルのスクリーンショットを `test-results/` に保存する。

`npm run build` はTypeScriptとVite。`npm run types` はWrangler設定に基づく型生成。`npx wrangler deploy --dry-run` でWorker bundleを検証する。本番のサービス開通やAI品質はdry-runだけでは確認できない。

## 限界と手動QA

スキーマ/記憶到達性の検証は、任意の複雑な論理式を解くものではない。現行のイベントは必須記憶・複数記憶のOR・信頼/復興/性格の下限を採用する。存在しない記憶、相互排他的な同一イベントの結果を両方要求する条件、総量を超える数値下限、循環だけの依存を検査する。一般の条件式の充足可能性を完全に証明するものではない。

実APIのプロンプト解釈品質、実プレイヤーの読書時間、感情的な余韻、長時間の端末別パフォーマンス、画面読み上げでの体験、悪意ある投稿への包括的対応は自動テストだけでは担保しない。

レビュー時には、原文を読んだ際に予測できる意味と修正後の動機が対応するか、救助に代価があるか、失敗がただの罰ではないか、同じ人物の後日談に矛盾がないかを確認する。イベント数を増やすより、違う教えで違う判断をする意味を優先する。
